01 / PROJECT EVIDENCE

SOC L1 Alert Investigation — Phishing Email Triage

COMPLETED SIMULATED SOC INVESTIGATION

Investigated a simulated SOC L1 phishing alert involving an inbound email containing a suspicious external onboarding link. The investigation used SIEM searches, URL analysis and network-log checks to determine whether the alert represented malicious activity.

OBJECTIVE

Determine whether the suspicious onboarding link was malicious and whether the user accessed it.

VERDICT

False Positive. The URL analysis returned CLEAN, related communications identified the domain as a third-party HR onboarding partner, and no URL access was found in the available firewall/proxy evidence.

TOOLS

Splunk / SIEM, TryDetectThis URL/IP analysis, email-event searches, proxy and firewall log searches.

SKILLS DEMONSTRATED

SOC L1 alert triage, phishing investigation, SIEM correlation, indicator analysis, network-log investigation, evidence-based classification and case reporting.

INVESTIGATION WORKFLOW
  1. Reviewed the inbound phishing alert and extracted the sender, recipient, subject and external URL.
  2. Correlated email events in the SIEM and reviewed related internal communication.
  3. Submitted the URL to TryDetectThis and recorded a CLEAN result.
  4. Queried proxy/firewall evidence for the domain and URL to look for access activity.
  5. Found no available evidence that the user accessed the URL.
  6. Classified the alert as a False Positive and documented the reasoning in a SOC case report.
KEY LESSON

The conclusion was based on available evidence rather than assumptions. In particular, I did not assume the user clicked the link because no evidence of URL access was present in the available logs.

01 / PROJECT EVIDENCE · TRYHACKME

High-Severity Malicious URL Alert Investigation

COMPLETED TRYHACKME SOC SIMULATOR LAB

This project was completed in the TryHackMe SOC Simulator. I investigated Alert 8816, a high-severity firewall alert triggered when a host attempted to access a blacklisted external URL. The firewall blocked the request, but the alert still required investigation to determine whether the activity was malicious and whether further response was needed.

LAB / PLATFORM

TryHackMe SOC Simulator — simulated Level 1 Security Operations Center investigation.

ALERT DETAILS

Alert ID: 8816
Severity: High
Source: Firewall
Rule: Blocked Websites
Outcome: True Positive; escalated for further investigation.

OBJECTIVE

Validate a high-severity alert by correlating firewall and email events, reviewing URL and IP indicators, recording the evidence, and recommending appropriate next steps.

TOOLS & EVIDENCE SOURCES

TryHackMe SOC Simulator, Splunk-style SIEM searches, firewall event data, email logs, and a URL/IP security-check tool.

WHAT I INVESTIGATED
  1. Reviewed the high-severity firewall alert and extracted its timestamp, action, source IP, destination IP, port, protocol, URL, and firewall rule.
  2. Searched for source IP 10.20.2.17 and reviewed an allowed web connection followed by the blocked request to the flagged destination.
  3. Checked destination IP 67.199.248.11 and the shortened URL http://bit.ly/3sHkX3da12340 in the lab’s URL/IP analysis tool; both were reported as malicious.
  4. Searched SIEM events for the same URL and found an inbound email shortly before the firewall event. The email used a package-delivery pretext and an urgent request to confirm shipping details.
  5. Connected the matching URL in the email with the blocked network request, while treating the timing as correlation rather than proof that the recipient clicked the link.
  6. Classified the alert as a True Positive and documented why it should be escalated for Level 2 review.
KEY FINDINGS
  • The firewall recorded a request from source IP 10.20.2.17 to destination IP 67.199.248.11 over TCP port 80, and the action was blocked.
  • The URL/IP checking tool marked both the shortened URL and destination IP as malicious.
  • An inbound email from urgents@amazon.biz with the subject “Your Amazon Package Couldn’t Be Delivered – Action Required” contained the same URL.
  • The suspicious email was recorded at 23:04:57.545 and the blocked firewall request at 23:06:11.545 on October 8, 2026.
  • The available evidence supports a true-positive malicious access attempt, but does not by itself prove successful access, device infection, or that the email recipient personally clicked the link.
FINAL DISPOSITION

True Positive. Escalate for further investigation because the URL and destination IP were flagged as malicious and the related email provides additional context.

RECOMMENDED NEXT STEPS

Identify the user/device behind the source IP; review endpoint and network logs around the event; determine whether the recipient interacted with the email or URL; keep the indicators blocked under policy; and check whether other users received the same message or attempted the same destination.

Alert TriageSIEM SearchLog CorrelationPhishing AnalysisIOC ValidationFirewall AnalysisTrue-Positive ClassificationCase DocumentationEscalation Reasoning
REAL-WORLD RELEVANCE

This workflow reflects common SOC L1 responsibilities: validate alerts with multiple sources, correlate email and network telemetry, distinguish confirmed malicious indicators from unproven assumptions, preserve key evidence, and escalate when the scope or impact needs deeper investigation.
